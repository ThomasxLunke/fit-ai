journal d'ingénierie — fit-ai

Du livre papier au programme généré

Fit-AI construit un programme de musculation personnalisé à partir de mesures morphologiques et d'un corpus de livres spécialisés, via un système RAG sur base vectorielle — avec deux modes de génération et une observabilité complète du pipeline.

1

Pipeline d'ingestion des livres

OCR puis nettoyage en deux passes — par règles d'abord, un seul passage LLM ensuite. Découpage en chunks par paragraphe entier, taille variable visant ~400 tokens, jamais coupé en deux. Embedding et stockage vectoriel dans Postgres/pgvector.

Des scripts d'entretien complètent le corpus au fil du temps : ajout de nouveaux livres, re-nettoyage, prévisualisation.

scripts/ocr-and-clean-book.ts lib/rule-based-cleanup.ts lib/context-cleanup.ts lib/chunk-book.ts scripts/embed-and-store-chunks.ts lib/vector-db.ts
2

Retrieval & génération du programme

13 requêtes fixes (un groupe musculaire + sa variante morphologie/blessure, plus une requête de structure), recherche top-k par similarité cosinus. Les chunks retenus sont fusionnés sous un budget de tokens puis passés à un LLM à sortie structurée, qui génère le programme et justifie chaque exercice.

lib/retrieval.ts lib/ai.ts lib/schema.ts scripts/test-generate-program.ts
3

Observabilité — Langfuse & Phoenix

Chaque étape (retrieval, embedding, génération) est tracée dans Langfuse, qui tient aussi le registre de prompts versionné — le prompt de génération n'est plus en dur dans le code. Les mêmes traces sont exportées en parallèle vers Phoenix, un second outil, sans double instrumentation. Les deux tournent en Docker local.

4

Évaluation RAGAS

Un script Python évalue les traces sur trois métriques sans référence. Juger la vraie requête de retrieval contre ses propres chunks — plutôt qu'une question reconstruite après coup contre tout le contexte fusionné — donne des scores nettement plus représentatifs :

Faithfulness0.54 → 0.87
Response relevancy0.38 → 0.90
Context precision0.48 → 0.98

5

RAG agentique

Boucle de correction par tag, plafonnée à deux tours : un juge note la suffisance du contexte récupéré (avant toute génération), propose une reformulation si besoin, et les chunks des deux tours sont accumulés — jamais remplacés — avant une seconde notation. Le mode agentique devance le mode classique sur les trois métriques RAGAS.

6

Mise en production

Les deux modes, jusque-là réservés au dev, sont désormais ouverts à tout utilisateur réel directement dans l'onboarding. La configuration Langfuse pointait vers localhost — ce qui aurait cassé toute génération, pas seulement l'agentique, dès le premier déploiement. Langfuse Cloud a été retenu pour la prod, Docker gardé pour le dev ; l'URL Phoenix est désormais configurable et simplement absente en prod si non définie.

components/onboarding-form.tsx lib/observability.ts .env.example
Reste à faire côté exploitation : créer le projet Langfuse Cloud, définir ses clés en variables d'environnement de prod, puis rejouer scripts/push-prompt-to-langfuse.ts avec ces clés avant le premier déploiement réel.
